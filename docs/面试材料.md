## 1. 项目讲稿

### 1.1 一句话版

"这是一个基于 KuaiRec 真实数据的短视频生成式推荐研究原型：把视频编成**层次语义 ID**、
用受限解码的序列模型**生成**候选。我做了同架构同预算的受控对照实验，完成了一个完整的研究闭环——
**从负结果出发（SID 生成最初弱于原生 ID），定位到碰撞率与内容特征两个瓶颈，
修复后两个协议上基本追平（98.5% / 97.3%），收敛实验（3 epoch，单种子）下进一步反超同预算对照，并推翻了自己早期的一个长尾误判。**"

### 1.2 30 秒版

"很多人说'生成式推荐'好，但我想验证**在什么条件下它成立**。
我用快手 KuaiRec 做了个生成式推荐系统，同架构同预算对照'生成语义 ID'与'生成原生视频 ID'。
故事分三段：① 初版语义 ID 生成**输了**——我没有藏这个负结果；
② 受控诊断把原因锁定在**碰撞率**（碰撞率 39%→0，recall@50 从 raw 的 40% 追到 98.5%），
神经内容特征再补一程；③ 我早期以为'SID 的优势在长尾'，进一步实验**推翻了这个说法**——
那是碰撞展开机制的副产物。**这个'自我修正'比任何涨点都更能说明我做研究的方式。**"

### 1.3 3 分钟版（骨架）

- **问题**（0:00–0:30）：生成式推荐（TIGER 路线）把物品编成语义 ID 再生成；
  我想验证两件事：SID 生成是否优于原生 ID 生成？瓶颈在哪？
- **方案**（0:30–1:10）：数据用 KuaiRec（1,411 用户 × 3,327 视频的**全观测稠密矩阵**做无偏评估）；
  内容特征（标题+类目 → TF-IDF+SVD / bge-small-zh）→ RQ-VAE（STE + 死码重启）→ 因果
  Transformer + **trie 受限解码 beam search**；对照 gen-raw（同架构直接生成视频 ID）与
  流行度/ItemCF/GRU4Rec 基线；**两套评估协议**（全观测稠密 + 标准留一负采样）。
- **结果**（1:10–2:20）：
  ① 初版是**负结果**：SID 生成弱于原生 ID（recall@50 0.0248 vs 0.0383）；
  ② 两点受控诊断：**碰撞处理**（码本扩容 +64% → "碰撞额外码位"方案在两个协议上追平：
     dense recall@50 达 raw 的 98.5%、采样协议 HR@10 达 97.3%）与**内容特征**
     （bge 编码器替代 TF-IDF：recall@50 +17%，碰撞率 22.2%→9.3%）；
     碰撞率 39.2%→22.2%→9.3%→0 对应 recall@50/raw 比值 40%→65%→76%→98.5%，
     **四点剂量-响应**是整条结论链最硬的证据；
  ③ **推翻自己的一个发现**："SID 的优势在长尾"是错的——长尾覆盖来自碰撞展开的
     任意成员机制（消除碰撞后长尾占比 8.0%→0.26%）；长尾需要显式探索机制。
- **反思**（2:20–3:00）：工程上定位过真 bug（缺 STE 导致码本坍缩；8→4 线程训练快 10 倍）；
  主表只训 1 epoch——我补的收敛与种子实验说明这不是上限：SID 随预算继续增益、
  3 epoch 下反超同预算对照（Q17）；行为 token 消融（Q18）与 SASRec 基线（Q19）
  也都是阴性结果 + 完整诊断；前缀缓存解码已完成（4.37×，557→106ms）；
  下一步：完整版 SASRec 调参、更深推理优化。

## 2. 高频追问与回答要点（全部对应真实实现与数字）

**Q1：什么是语义 ID？为什么要它？**
把物品的**内容**编码后用残差量化（RQ-VAE）变成一串层级码字（如 3 层 × 1024 码本）。
它替代随机初始化的 item_id：冷启动物品有内容就有 ID；相似物品共享前缀，偏好可迁移。
出处：TIGER（NeurIPS 2023）用 RQ-VAE 做生成式检索；RQ-VAE 来自 Lee et al. CVPR 2022。

**Q2：你的 RQ-VAE 怎么实现的？**
标准化内容特征 → MLP 编码 32 维 → 逐级"量化并减去残差" → MLP 解码；
损失 = 重建 + 码本 + 0.25×承诺；**直通估计（STE）**把量化梯度传给编码器；
每 100 轮把未使用的码字重置为随机残差（防坍缩）；训练 600 轮（CPU 约 7~11 分钟）。

**Q3：为什么有碰撞率？怎么处理的？**
两个来源要讲清：① 编码器输出分布聚集，码本理论容量用不满（v2 时 22% 碰撞）；
② 处理方案有两条路——"解码时展开候选组"（初版）与"碰撞追加额外码位"（B3，最终采用）。
**B3 是关键实验**：4 级码让 10,728 个 SID 全唯一，解码从"按序展开任意成员"变成
"模型学会在组内选成员"，dense recall@50 **+52%**、两个协议上追平 raw。
副作用：每个物品多 1 个 token（解码 4 步，单用户延迟 279→557ms）。

**Q4：受限解码怎么实现的？**
对全部合法 SID 建 trie；beam search 每步只允许 trie 当前前缀下的码字 token，
逐级生成；beam 内碰撞组展开、去重；raw 变体单步生成。实现都在 `models/seqgen.py`
（约 60 行核心逻辑），有单元测试覆盖（只生成合法视频、无重复）。

**Q5：讲讲你的核心对照实验（SID vs 原生 ID）——最后谁赢了？**
这是整个项目的骨架，我按三段讲：
① **初版负结果**：同架构同预算下 SID 生成弱于原生 ID（recall@50 0.0248 vs 0.0383）——
我没有把它包装成正收益；
② **受控诊断**：锁定两个瓶颈并逐一验证——碰撞处理（四点剂量-响应：碰撞率
39.2%→22.2%→9.3%→0，对应 recall@50/raw 比值 40%→65%→76%→98.5%）与内容特征
（bge-small-zh 替代 TF-IDF：recall@50 +17%，碰撞率 22.2%→9.3%）；
③ **最终结论**：修复后 b3 在**两个协议**上都基本追平原生 ID（dense recall@50 达 98.5%、
ndcg@10 反超 4%；采样协议 HR@10 达 97.3%），代价是解码多一步、延迟约 2 倍。
④ **补强（预算与噪声）**：3 epoch 收敛对照 + 三种子方差（详见 Q17）——"追平"不是终点：
扩大预算后 sid-b3 四项反超同预算 raw（单种子）。
**这个从负结果到追平的闭环，比一句"我涨点了"信息量大得多。**

**Q6：所以语义 ID 生成的优势到底在哪？（长尾那个发现还成立吗）**
**不成立了——这是我主动更正的一个结论。** 早期我观察到 SID 版本能命中零曝光冷启动物品、
Top-50 长尾占比 5~8%，当时把它解释成"语义 ID 的长尾优势"。后来 B3 实验推翻了这个解释：
那部分长尾覆盖来自**碰撞展开的"任意成员"机制**（按 video_id 顺序取组成员，等于随机塞入
长尾视频）；消除碰撞后长尾占比降到 0.26%，回到与原生 ID 一致的行为。
**修正后的答案**：SID 生成本身不自动带来长尾覆盖，需要显式的多样性/探索机制。
后来又用"首次曝光时间"口径（E5）和多样性指标（E6）做了两轮复验：**上新目标几乎没有任何方法
能命中；唯一会给上新物品曝光、以及在新颖性上领先的信号，全部来自 SID 家族，且都随碰撞消除而
回落**（新颖性 v1 13.92 → b3 11.99 ≈ raw 11.95）——"碰撞副产物"这一解释在三个维度上独立复现。
我更愿意讲这个"推翻自己"的过程——它说明我的结论是实验得出的，不是预设立场的。

**Q7：为什么用全观测稠密矩阵评估？**
小矩阵 99.6% 密度：**每个（用户×视频）的真实反馈都可观测**，
排序指标没有"未曝光≠不喜欢"的偏差——这是 KuaiRec 的设计初衷（CIKM 2022）。
代价是用户观看密度极高（人均 3,000+ 交互），任务形态接近"预测下一时段观看集合"，
所以指标绝对值不能与其他稀疏数据集的论文数字直接比，我只做**跨方法相对比较**。

**Q8：为什么 ItemCF 这么强？**
稠密数据下"续看同一小众内容带"是强模式；ItemCF 用全库打分取 Top-50，
天然契合。这本身是有意义的结论：**在稠密数据上强基线比"生成式"更难对付**。
从多样性看它也偏"窄"（E6：新颖性 11.46，低于生成式）——强与窄是一体两面。
（另：我修过它的两个口径问题：相似度对角线置零、候选排除已看物品。）

**Q9：训练规模为什么这么小？**
本机 8 核 CPU、无有效 GPU：150k 样本 1 epoch。
标定时发现 8 线程因线程超订只有 19 samples/s，**4 线程 206 samples/s（10 倍）**——
这类工程细节是 CPU 训练的常态。更多算力下的计划见 Q13。

**Q10：beam 大小怎么选？**
beam 是"候选预算/延迟"旋钮，我扫出了完整曲线（b3：beam 1/2/5/10/20/50）：
**top-10 质量在 beam≈20 饱和**——ndcg@10 0.5179 = beam50 的 0.5178，但延迟只要
30ms（28%）；beam=10 保留 90% 质量、延迟 13%；而 recall@50 这类"清单长度"指标
受候选数约束（beam50 0.0378 vs beam20 0.0151），走"生成粗排 + 精排"才需要大 beam。
**结论：直出 top-10 用 beam20，做粗排候选用 beam50 以上——按下游用途选点。**
（延迟为 D1 前缀缓存解码同会话重测值。）

**Q11：生成式检索的延迟怎么压进线上预算？**
我做了实际优化（D1）：原解码每级对每条 beam 行重算整段前缀，我实现
**context 前缀 K/V 缓存**（每用户前缀只算一次，各步仅前向 ≤3 个新 token），
并做了三重等价性验证（单测 / 12,700 条 top-50 列表全量对照 / 归档哈希一致）。
结果：**同条件对照 4.37×（568→130ms/用户）；全量重测 b3 从 557ms 降到 106ms**，
beam20 时只要 30ms 且 top-10 质量不降。对照原生 ID 单步生成约 3.5ms，差距明显缩小；
继续压的方向：增量 KV、KV 量化、蒸馏单步模型。**"能不能把生成成本压进线上预算"
是判断生成式推荐落地性的核心问题——而它是可以工程化解决的。**

**Q12：你和 TIGER 的差距在哪？**
诚实的差距清单：内容编码器（TF-IDF+SVD vs Sentence-T5）、碰撞处理（展开 vs 追加位）、
训练预算（1 epoch × 150k vs 大规模）、评估（KuaiRec vs Amazon）。
**我的增量不在模型规模，而在**：同一架构下的受控对照实验、负结果归因、
全观测无偏评估、以及长尾/冷启动的条件性结论。

**Q13：如果给你更多算力/时间，你怎么做？**
已经完成的六项：① 4 级 SID（B3）与神经内容编码器（B1，bge-small-zh）；
② **多 epoch 收敛对照**：sid-b3 与 raw 各 3 epoch 同预算——sid-b3 四项全面反超
（dense recall@50 +15.4%、ndcg@10 +24.7%，采样 +1.5% / +1.6%，单种子），
且其 1→3 epoch 增益大于 raw（raw 稠密指标回落）；
③ **三种子方差量化**：dense recall@50 残余差距在噪声内（-0.05±0.08pp）、
采样协议剩稳定小劣势（-1.9±0.6pp），随预算翻转；
④ **行为 token 消融（负结果）与 beam Pareto 曲线**：行为 token 未检测到收益（Q18）；
top-10 质量 beam≈20 即饱和（Q10）；
⑤ **SASRec-lite 标准基线（阴性结果 + 回声陷阱诊断链，Q19）**；
⑥ **前缀缓存解码（D1）**：同条件 4.37×、b3 557→106ms/用户（Q11）；冷启动定义细化（E5）
与多样性/新颖性指标（E6）也已完成。
按优先级剩余：① 完整版 SASRec（超参搜索——本版为 lite 档，见 Q19）；
② 更深推理优化（增量 KV/量化——D1 为最小版）；
③ 若走线上：分层"生成粗粒度 + 精排"路线（HiGR 式）。

**Q14：这个项目里你遇到过的最难的问题？**
两个：① RQ-VAE 训练后 10,728 个视频只生成 593 个唯一 SID——
定位到实现缺 **STE**（量化处梯度断流，编码器只被承诺损失拉向少数码字）；
补 STE + 死码重启 + 特征标准化后到 9,114。② 训练慢 10 倍——
8 线程超订，改 4 线程解决。两个都已固化为测试或注释。

**Q15：你个人贡献是什么（别夸大）？**
独立完成全部代码（数据管道、RQ-VAE、生成模型、受限解码、评估、CLI、测试）；
对照实验与改进实验设计；全观测评估协议；负结果归因。
**不声称**：复现了 TIGER 的全部结论、达到 SOTA、任何线上收益。

**Q16：你用了两套评估协议（稠密全观测 + 标准留一负采样）——为什么不只用一套？两套的结论有什么不同？**
这是个好问题，本身也是我项目的一个发现。稠密协议像"推荐真实候选列表"，标准协议像
"从随机候选里挑出下一个"——**协议会改变方法排序**：稠密协议下 ItemCF 断层第一
（0.0585 vs 生成式 0.0248），标准协议下 ItemCF（HR@10 0.517）与 GRU 基线（0.501）
几乎同档。但两条核心结论**跨协议一致**：① SID 生成弱于原生 ID（差距从 65% 收窄到 85%）；
② 降碰撞的改进两个协议都复现（+64% / +41%）。这说明：**单协议的单点对照容易被质疑，
跨协议复验过的结论才站得住**——这也是我从这个项目里学到最重要的事之一。
（注：Q16 讲的是 1 epoch 主实验的跨协议对照；收敛实验把终点推进到 3 epoch 反超——见 Q17。）

**Q17：你的主表只训 1 epoch、一些对照是单种子——"欠训练"和"种子噪声"会不会推翻你的结论？**
这正是我自己补的两个实验，直接上数据：
① **收敛**：sid-b3 与 raw 各训 3 epoch（seed42）。sid-b3 随预算持续增益
（四项指标 +3.7%~+10.5%），raw 的稠密指标反而回落（-11.5% / -7.8%，过拟合迹象）——
3 epoch 同预算下 **sid-b3 四项全面反超**（dense +15.4% / +24.7%，采样 +1.5% / +1.6%）。
"欠训练"确实存在，但方向对 SID 有利。附带一个方法论观察：两个模型的验证损失都在上升，
而 sid-b3 的排序指标全升——**教师强制损失不能替代下游评估**。
② **噪声**：seed 42/43/44 各 1 epoch、双协议配对差。dense recall@50 差距
-0.046±0.083pp 三种子跨零——**在噪声内**；dense ndcg@10 优势（+1.77±0.45pp）
与采样协议劣势（HR@10 -1.92±0.56pp）方向三种子全一致——**超噪声但幅度小**。
③ **诚实边界**：3 epoch 对照是单种子（以 1 epoch 三种子噪声为参照标尺：dense 两项领先
幅度 6~25 倍标尺、采样两项仅约 1 倍）；更大预算与"多种子 × 多 epoch"矩阵未跑，
不声称调优上限。

**Q18：你序列里加了 watch_ratio 行为 token——它真的有用吗？**
我专门做了消融：新变体 sid-b3-na 关闭行为 token，其余与 b3 完全一致，同种子对照。
结果五项指标全部方向为负但很小——**稠密协议三项完全落在 b3 三种子噪声分布内**、
采样两项略低于下沿 0.15~0.27pp。**结论：在这套配置下行为 token 没有可检测的收益，
这是个负结果，我如实写进了报告。** 可能的原因（未验证）：目标只生成 SID、
行为 token 只修饰 context；五档分桶信号与"看过"高度冗余；1 epoch 预算学不动
细粒度信号。**面试价值：能讲清楚"我怎么用受控消融否定自己的一个设计假设"，
比多讲一个涨点更能证明实验素养。**

**Q19：你有面向工业标准的 SASRec 基线吗？**
有，而且是这个项目里我做得最"较真"的一个实验：
① **实现与验证**：自实现 SASRec-lite（因果自注意力 + 全词表交叉熵，与生成式模型同数据预算），
5 项单测 + smoke + 两轮训练确定性复现，评估链路手工复算核验；
② **结果（阴性）**：稠密 recall@50 0.0286、采样 HR@10 0.334——两个协议都弱于 GRU4Rec-lite
（0.0371 / 0.501）和生成式模型，我没有藏这个结果；
③ **诊断链**：排除实现错误后锁定机制——训练期"回看回声"是高频模式（28.1% 的 target 藏在
最近 20 个行为里），模型学会了"优先推刚看过的最后一个视频"（LOO 上末项得分 ≥ 真实目标的
比例 84.7%）；而回看率随数据集时间大幅衰减（训练窗 28.1% → 未来窗 7.2% → 最终项 3.4%），
策略在评估期系统性错位；容量翻倍反而放大回声（d64→d128：0.334→0.208）；
④ **边界**：结论仅限此 lite 档配置（20 项窗口、无超参搜索），不代表完整 SASRec。
**面试价值：一个标准基线从实现、验证、阴性结果到机制归因的完整闭环。**

## 3. 诚实边界（面试中不要说的）

1. 不要说"我的生成式模型超过/接近了某线上系统"——本项目是**离线研究原型**；
2. 不要说"复现了 TIGER"——只借鉴其思路（语义 ID + 生成式检索），实现与规模均不同；
3. 不要引用本项目 recall 数字与其他数据集论文对比——评估协议与数据密度完全不同；
4. 不要把"待运行"的实验说成已完成（完整版 SASRec、增量 KV/量化等更深优化）；
   3 epoch 反超是单种子结论——说"收敛预算下反超"可以，说"调优后全面超越"不行；
   行为 token 消融是**负结果**（Q18），如实讲，不要辩护成"再调调就有用"；
   SASRec-lite 的阴性结果（Q19）是"本 lite 档配置"的结论，不要说成"生成式/GRU 一定优于 SASRec"级的方法论结论。
