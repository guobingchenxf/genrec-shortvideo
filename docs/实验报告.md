## 2. 语义 ID（RQ-VAE）

配置：内容特征标准化 → MLP 编码 32 维潜变量 → 3 级残差量化（各 1024 或 256 码本）→ MLP 解码；
损失 = 重建 MSE + 码本损失 + 0.25×承诺损失；直通估计（STE）；每 100 轮死码重启；600 轮。

| 版本 | 码本 | 训练耗时（实测） | 重建损失 | 唯一 SID | 碰撞率 | 码本使用（3 级） |
|---|---|---|---|---|---|---|
| v1 | 256³ | 416.5s | 0.0614 | 7,699 | 39.2% | 256 / 256 / 256 |
| **v2（改进）** | **1024³** | 669.8s | 0.0287 | **9,114** | **22.2%** | 1024 / 1017 / 1005 |

**修复记录（重要）**：初版实现缺少 STE，编码器收不到重建梯度 → 码本坍缩（10,728 视频仅 593 个唯一 SID）。
修复 STE 后同配置达到 7,699 个唯一 SID。此坑已固化为回归测试（`tests/test_rqvae.py`）。

## 4. 评估协议（本项目核心方法学）

- **全观测无偏评估**：稠密小矩阵按时间切 80%/20%；前 80% 行为为 context，后 20% 观看集合为 targets（平均 ≈637 视频/用户）。全观测性质消除了稀疏数据"采样负样本"的曝光偏差。
- **统一排除规则**：所有方法剔除用户 context 内已看视频（ItemCF 对角线置零）。
- **指标**：Recall@K、NDCG@10、HitRate@K、Coverage@50；延迟按每用户平均（实测）。
- **统计特性声明**：用户观看密度极高（人均 3,000+ 交互），该任务对"续看小众带"类方法（ItemCF）天然友好；**指标绝对值不可与其他稀疏数据集论文数字直接比较，跨方法相对比较才是有效信号**。

## 6. 关键分析

### 6.1 核心对照：SID 生成 vs 原生 ID 生成（同架构、同预算、唯一变量=token 化方式）

- v1：gen-sid 0.0151 vs gen-raw 0.0383（recall@50）——**SID 生成显著弱于原生 ID**；
- 改进后 v2：0.0248（**+64%**），差距缩小但未追平。
- **条件性结论**：① 碰撞率是主要瓶颈之一（假设方向被验证）；② 剩余差距归因于内容特征强度（TF-IDF+SVD 弱）、残余 22% 碰撞、三级自回归误差累积、1 epoch 训练预算。

### 6.2 beam 消融（50 → 10）

| 方法 | recall@50 | ndcg@10 | 延迟 ms/用户 |
|---|---|---|---|
| gen-sid beam50 | 0.0151 | 0.2428 | 203 |
| gen-sid beam10 | 0.0124 | 0.2327 | 69.5 |
| gen-sid-v2 beam50 | 0.0248 | 0.3600 | 282 |
| gen-sid-v2 beam10 | 0.0072 | 0.3465 | 78.1 |

解读：beam 是**候选预算/延迟旋钮**（recall@50 受预算上限约束）；同预算下 v2 全面优于 v1。

### 6.3 长尾/冷启动分桶（桶按训练期热度；micro 命中率）

| 方法 | pop=0 | pop 1-4 | pop 5-49 | pop 50-499 | pop 500+ | Top-50 长尾占比 |
|---|---|---|---|---|---|---|
| 流行度 / ItemCF / gru-raw | 0 | 0 | 0 | ≈0 | 0.041~0.064 | ≈0 |
| gen-sid | 0 | 0.0084 | 0.0005 | 0.0118 | 0.0156 | 8.0% |
| **gen-sid-v2** | **0.0082** | — | — | 0.0067 | 0.0268 | 5.2% |

**核心发现**：只有语义 ID 生成能命中**训练期零曝光（pop=0）的冷启动物品**，且 Top-50 长尾占比 5~8%（其余方法≈0）。
**→ 回答「什么条件下 SID 生成有优势」：长尾/冷启动场景，而非头部效率。**

> **后续修正（2026-10-06，见 §6.5）**：B3 实验表明，本节的长尾覆盖优势有相当部分来自
> 碰撞展开的"任意成员"机制；在消除碰撞的配置下该优势消失（长尾占比 8.0%→0.26%）。
> 更准确的表述：**"展开式解码在特定配置下会带来长尾曝光副产物"，而非
> "语义 ID 生成本身具备长尾优势"。**

### 6.4 标准协议复验（C1/C3：留一法 + 100 负采样）

方法：大矩阵每用户取最后一条交互为目标、其前最近 20 条为 context（含真实行为 token）；
100 个"不在用户历史中"的随机负样本（seed=42）；**生成模型用教师强制序列似然打分**
（候选 token 序列的 log-prob 之和，逐候选批处理），与基线共用同一候选集；
指标 HR@10 / NDCG@10（101 个候选内排名，并列按严格大于计数）。
样本：按 user_id 升序前 **2,000** 个用户；**95.5% 的目标位于训练窗口之后** → 近似"未来测试"，
比文献"训练见完整历史"的留一法更严格；绝对值不与论文数字直接比较。

| 方法 | HR@10 | NDCG@10 | 打分耗时（实测） |
|---|---|---|---|
| random（参考锚点） | 0.0920 | 0.0422 | 0.0s |
| 流行度 | 0.1585 | 0.0805 | 0.7s |
| ItemCF | 0.5170 | 0.2915 | 1.4s |
| gen-sid (v1) | 0.2920 | 0.1419 | 614s |
| gen-sid-v2 | 0.4110 | 0.2163 | 646s |
| gen-raw | 0.4825 | 0.2779 | 319s |
| gru-raw | 0.5010 | 0.2767 | 103s |

（random 理论值 10/101 ≈ 0.099，实测 0.092 —— 锚点正常。）

**跨协议对照结论**：
1. **核心负结果跨协议成立、但差距大幅收窄**：sid-v2 / raw 的 HR@10 比值从稠密协议的
   65%（0.0248/0.0383）收窄到 **85%**（0.4110/0.4825）——换协议没有翻转结论。
2. **碰撞率归因跨协议稳健**：v1→v2 的提升在两个协议下一致复现
   （稠密协议 recall@50 +64%；标准协议 HR@10 +41% 相对）——"碰撞是主要瓶颈之一"
   不再依赖单一协议或单一指标。
3. **协议本身改变方法排序**：稠密协议下 ItemCF 断层第一（0.0585 vs 0.0248=2.4×），
   标准协议下 ItemCF（0.517）与 gru-raw（0.501）、gen-raw（0.4825）几乎同档——
   "续看小众带"的稠密任务会严重放大相似度方法的优势。**评估协议是结论的一部分。**
4. 标准协议下生成式模型仍未胜出（gen-raw 0.4825 < gru-raw 0.501 ≈ ItemCF 0.517），
   残余差距指向内容编码器与训练预算（对应 B / A 组实验）。
   **后续（§6.5 B 组已完成）**：残余差距的主因是碰撞处理而非训练预算——
   b3 在该协议上 HR@10 达 raw 的 97.3%。

### 6.5 B 组：特征消融与碰撞处理对照（B1/B2/B3）

**配置矩阵（唯一变量链）**：

| 版本 | 内容特征 | 语义 ID 方案 | 碰撞率 | 唯一 SID |
|---|---|---|---|---|
| gen-sid (v1) | TF-IDF+SVD64 | 3 级 × 256 码本 | 39.2% | 7,699 |
| gen-sid-v2 | TF-IDF+SVD64 | 3 级 × 1024 码本 | 22.2% | 9,114 |
| gen-sid-b1 | **bge-small-zh → PCA64** | 3 级 × 1024 码本 | **9.31%** | 9,925 |
| gen-sid-b3 | TF-IDF+SVD64 | v2 码 + **碰撞额外码位**（4 级） | **0%** | 10,728 |

（bge：512d → PCA64，解释方差 **0.648** vs TF-IDF+SVD64 的 0.350；CPU 编码 10,728 条用时 427s。）

**B2 特征消融（TF-IDF → 神经特征，其余不变）**：dense recall@50 0.0248 → **0.0290（+17%）**、
ndcg@10 0.360 → 0.395；碰撞率同步 22.2% → 9.3%。采样协议 HR@10 0.4110 → 0.4255（+3.5%）。

**B3 碰撞处理对照（"展开" → "碰撞额外码位"）**：dense recall@50 0.0248 → **0.0378（+52%）**、
ndcg@10 0.360 → **0.518**；采样协议 HR@10 0.4110 → **0.4695（+14%）**。
**b3 在两个协议上都基本追平原生 ID 生成**：dense recall@50 达 raw 的 **98.5%**、
ndcg@10 为 raw 的 **104%**；采样协议 HR@10 达 raw 的 **97.3%**。
机制解释（经逐用户抽查验证，两模型 top-10 重合仅 40%）：v2 的"展开"在碰撞组内
按 video_id 顺序取成员（相当于任意成员），而额外码位让模型**学会在组内选成员**——
同时消掉了"前缀歧义"与"任意成员"两个损失来源。

**剂量-响应（recall@50 / raw 比值 vs 碰撞率）**：
39.2% → 39.5%；22.2% → 64.8%；9.3% → 75.6%；**0% → 98.5%**。
"碰撞率是 SID 生成弱势的主导因素"从单点对照升级为**四点趋势证据**。

**对"长尾优势"的重要修正（如实记录）**：B 组分桶分析显示，早期版本的长尾覆盖
（v1 Top-50 长尾占比 8.0%、v2 5.2%）有相当部分来自**碰撞展开的"任意成员"机制**——
按 video_id 顺序展开等于随机把一批长尾视频塞进列表。消除碰撞（b3）后长尾占比
降至 **0.26%**，回到与原生 ID 生成一致的行为（raw 0%、itemcf 0.01%）。
**结论修正：语义 ID 生成本身不自动带来长尾/冷启动覆盖；早期的长尾信号是配置副产物，
要做长尾覆盖需要显式的多样性/探索机制。**

**代价**：b3 每个物品多 1 个 token（解码 4 步而非 3 步），dense 评估单用户延迟
279ms（b1）→ 557ms（b3）（beam=50，CPU）。

## 7. 负结果与如实声明（不包装）

1. **初版配置下**，"SID 生成优于原生 ID 生成"（TIGER 论文的隐含假设）**不成立**；
   但**后续 B 组（§6.5）把它修正为"基本追平"**：修复碰撞处理与内容特征后，
   b3 在两个协议上达到 raw 的 97.3%~98.5%。**"负结果 → 受控诊断 → 修复 → 追平"
   的完整闭环，以及期间主动推翻的一个长尾结论（§6.3 修正），是本项目的核心研究回答。**
2. 所有生成模型仅训练 1 epoch（150k 样本），未做超参搜索；数字代表"轻量预算下的结论"，不是调优后的上限。
3. 合成数据仅用于单元测试；所有评估数字均来自真实 KuaiRec 数据。
4. 本项目是离线研究原型：**无线上 A/B、无线上收益声明**。

**待运行（明确列出）**：行为 token 消融（on/off）、更多 epoch 的收敛/缩放曲线、
SASRec 标准基线、prefix 共享/KV 缓存推理优化、多种子方差、更细粒度的冷启动定义（按上线时间）。

## 8. 工程问题与修复记录（面试可讲）

| 问题 | 表现 | 根因与修复 |
|---|---|---|
| RQ-VAE 码本坍缩 | 唯一 SID 仅 593 | 缺 STE → 编码器无重建梯度；补 STE + 死码重启 + 特征标准化 |
| CPU 训练慢 10 倍 | 19 samples/s | 8 线程超订；改 4 线程 → 206 samples/s |
| 检查点加载失败 | RuntimeError(state_dict) | 位置嵌入 max_len 训练/推理不一致；存入检查点并统一重建 |
| caption 解析崩溃 | pandas Buffer overflow | 换 python 引擎；8 行缺字段置空串（发现类型污染 NaN） |
| 数据下载不可行 | 官方源 42 KB/s | 多源策略（镜像矩阵+官方小文件），校验后使用并全量披露 |

## 9. 复现命令（等价于本报告）

```bash
python -m genrec.cli download && python -m genrec.cli validate
python -m genrec.cli prepare
python -m genrec.cli train-rqvae            # v1；v2 加 --tag v2
python -m genrec.cli train-gen --variant sid
python -m genrec.cli train-gen --variant sid-v2
python -m genrec.cli train-gen --variant raw
python -m genrec.cli train-gen --variant raw-gru
python -m genrec.cli evaluate               # 六方法主表
python -m genrec.cli evaluate --methods gen-sid,gen-sid-v2 --beam 10   # beam 消融
python scripts/analyze_buckets.py           # 长尾分桶
```
