## 2. 语义 ID（RQ-VAE）

配置：内容特征标准化 → MLP 编码 32 维潜变量 → 3 级残差量化（各 1024 或 256 码本）→ MLP 解码；
损失 = 重建 MSE + 码本损失 + 0.25×承诺损失；直通估计（STE）；每 100 轮死码重启；600 轮。

| 版本 | 码本 | 训练耗时（实测） | 重建损失 | 唯一 SID | 碰撞率 | 码本使用（3 级） |
|---|---|---|---|---|---|---|
| v1 | 256³ | 416.5s | 0.0614 | 7,699 | 39.2% | 256 / 256 / 256 |
| **v2（改进）** | **1024³** | 669.8s | 0.0287 | **9,114** | **22.2%** | 1024 / 1017 / 1005 |

**修复记录（重要）**：初版实现缺少 STE，编码器收不到重建梯度 → 码本坍缩（10,728 视频仅 593 个唯一 SID）。
修复 STE 后同配置达到 7,699 个唯一 SID。此坑已固化为回归测试（`tests/test_rqvae.py`）。

## 4. 评估协议（本项目核心方法学）

- **全观测无偏评估**：稠密小矩阵按时间切 80%/20%；前 80% 行为为 context，后 20% 观看集合为 targets（平均 ≈637 视频/用户）。全观测性质消除了稀疏数据"采样负样本"的曝光偏差。
- **统一排除规则**：所有方法剔除用户 context 内已看视频（ItemCF 对角线置零）。
- **指标**：Recall@K、NDCG@10、HitRate@K、Coverage@50；延迟按每用户平均（实测）。
- **统计特性声明**：用户观看密度极高（人均 3,000+ 交互），该任务对"续看小众带"类方法（ItemCF）天然友好；**指标绝对值不可与其他稀疏数据集论文数字直接比较，跨方法相对比较才是有效信号**。

## 6. 关键分析

### 6.1 核心对照：SID 生成 vs 原生 ID 生成（同架构、同预算、唯一变量=token 化方式）

- v1：gen-sid 0.0151 vs gen-raw 0.0383（recall@50）——**SID 生成显著弱于原生 ID**；
- 改进后 v2：0.0248（**+64%**），差距缩小但未追平。
- **条件性结论**：① 碰撞率是主要瓶颈之一（假设方向被验证）；② 剩余差距归因于内容特征强度（TF-IDF+SVD 弱）、残余 22% 碰撞、三级自回归误差累积、1 epoch 训练预算。

### 6.2 beam 消融（50 → 10）

| 方法 | recall@50 | ndcg@10 | 延迟 ms/用户 |
|---|---|---|---|
| gen-sid beam50 | 0.0151 | 0.2428 | 203 |
| gen-sid beam10 | 0.0124 | 0.2327 | 69.5 |
| gen-sid-v2 beam50 | 0.0248 | 0.3600 | 282 |
| gen-sid-v2 beam10 | 0.0072 | 0.3465 | 78.1 |

解读：beam 是**候选预算/延迟旋钮**（recall@50 受预算上限约束）；同预算下 v2 全面优于 v1。

### 6.3 长尾/冷启动分桶（桶按训练期热度；micro 命中率）

| 方法 | pop=0 | pop 1-4 | pop 5-49 | pop 50-499 | pop 500+ | Top-50 长尾占比 |
|---|---|---|---|---|---|---|
| 流行度 / ItemCF / gru-raw | 0 | 0 | 0 | ≈0 | 0.041~0.064 | ≈0 |
| gen-sid | 0 | 0.0084 | 0.0005 | 0.0118 | 0.0156 | 8.0% |
| **gen-sid-v2** | **0.0082** | — | — | 0.0067 | 0.0268 | 5.2% |

**核心发现**：只有语义 ID 生成能命中**训练期零曝光（pop=0）的冷启动物品**，且 Top-50 长尾占比 5~8%（其余方法≈0）。
**→ 回答「什么条件下 SID 生成有优势」：长尾/冷启动场景，而非头部效率。**

> **后续修正（2026-10-06，见 §6.5）**：B3 实验表明，本节的长尾覆盖优势有相当部分来自
> 碰撞展开的"任意成员"机制；在消除碰撞的配置下该优势消失（长尾占比 8.0%→0.26%）。
> 更准确的表述：**"展开式解码在特定配置下会带来长尾曝光副产物"，而非
> "语义 ID 生成本身具备长尾优势"。**

### 6.4 标准协议复验（C1/C3：留一法 + 100 负采样）

方法：大矩阵每用户取最后一条交互为目标、其前最近 20 条为 context（含真实行为 token）；
100 个"不在用户历史中"的随机负样本（seed=42）；**生成模型用教师强制序列似然打分**
（候选 token 序列的 log-prob 之和，逐候选批处理），与基线共用同一候选集；
指标 HR@10 / NDCG@10（101 个候选内排名，并列按严格大于计数）。
样本：按 user_id 升序前 **2,000** 个用户；**95.5% 的目标位于训练窗口之后** → 近似"未来测试"，
比文献"训练见完整历史"的留一法更严格；绝对值不与论文数字直接比较。

| 方法 | HR@10 | NDCG@10 | 打分耗时（实测） |
|---|---|---|---|
| random（参考锚点） | 0.0920 | 0.0422 | 0.0s |
| 流行度 | 0.1585 | 0.0805 | 0.7s |
| ItemCF | 0.5170 | 0.2915 | 1.4s |
| gen-sid (v1) | 0.2920 | 0.1419 | 614s |
| gen-sid-v2 | 0.4110 | 0.2163 | 646s |
| gen-sid-b1 | 0.4255 | 0.2237 | 796s |
| gen-sid-b3 | 0.4695 | 0.2677 | 1129s |
| gen-raw | 0.4825 | 0.2779 | 319s |
| gru-raw | 0.5010 | 0.2767 | 103s |
| sasrec（SASRec-lite） | 0.3340 | 0.1929 | 1.2s |

（random 理论值 10/101 ≈ 0.099，实测 0.092 —— 锚点正常。）

**跨协议对照结论**：
1. **核心负结果跨协议成立、但差距大幅收窄**：sid-v2 / raw 的 HR@10 比值从稠密协议的
   65%（0.0248/0.0383）收窄到 **85%**（0.4110/0.4825）——换协议没有翻转结论。
2. **碰撞率归因跨协议稳健**：v1→v2 的提升在两个协议下一致复现
   （稠密协议 recall@50 +64%；标准协议 HR@10 +41% 相对）——"碰撞是主要瓶颈之一"
   不再依赖单一协议或单一指标。
3. **协议本身改变方法排序**：稠密协议下 ItemCF 断层第一（0.0585 vs 0.0248=2.4×），
   标准协议下 ItemCF（0.517）与 gru-raw（0.501）、gen-raw（0.4825）几乎同档——
   "续看小众带"的稠密任务会严重放大相似度方法的优势。**评估协议是结论的一部分。**
4. 标准协议下生成式模型仍未胜出（gen-raw 0.4825 < gru-raw 0.501 ≈ ItemCF 0.517），
   残余差距指向内容编码器与训练预算（对应 B / A 组实验）。
   **后续（§6.5 B 组已完成）**：残余差距的主因是碰撞处理而非训练预算——
   b3 在该协议上 HR@10 达 raw 的 97.3%。

### 6.5 B 组：特征消融与碰撞处理对照（B1/B2/B3）

**配置矩阵（唯一变量链）**：

| 版本 | 内容特征 | 语义 ID 方案 | 碰撞率 | 唯一 SID |
|---|---|---|---|---|
| gen-sid (v1) | TF-IDF+SVD64 | 3 级 × 256 码本 | 39.2% | 7,699 |
| gen-sid-v2 | TF-IDF+SVD64 | 3 级 × 1024 码本 | 22.2% | 9,114 |
| gen-sid-b1 | **bge-small-zh → PCA64** | 3 级 × 1024 码本 | **9.31%** | 9,925 |
| gen-sid-b3 | TF-IDF+SVD64 | v2 码 + **碰撞额外码位**（4 级） | **0%** | 10,728 |

（bge：512d → PCA64，解释方差 **0.648** vs TF-IDF+SVD64 的 0.350；CPU 编码 10,728 条用时 427s。）

**B2 特征消融（TF-IDF → 神经特征，其余不变）**：dense recall@50 0.0248 → **0.0290（+17%）**、
ndcg@10 0.360 → 0.395；碰撞率同步 22.2% → 9.3%。采样协议 HR@10 0.4110 → 0.4255（+3.5%）。

**B3 碰撞处理对照（"展开" → "碰撞额外码位"）**：dense recall@50 0.0248 → **0.0378（+52%）**、
ndcg@10 0.360 → **0.518**；采样协议 HR@10 0.4110 → **0.4695（+14%）**。
**b3 在两个协议上都基本追平原生 ID 生成**：dense recall@50 达 raw 的 **98.5%**、
ndcg@10 为 raw 的 **104%**；采样协议 HR@10 达 raw 的 **97.3%**。
机制解释（经逐用户抽查验证，两模型 top-10 重合仅 40%）：v2 的"展开"在碰撞组内
按 video_id 顺序取成员（相当于任意成员），而额外码位让模型**学会在组内选成员**——
同时消掉了"前缀歧义"与"任意成员"两个损失来源。

**剂量-响应（recall@50 / raw 比值 vs 碰撞率）**：
39.2% → 39.5%；22.2% → 64.8%；9.3% → 75.6%；**0% → 98.5%**。
"碰撞率是 SID 生成弱势的主导因素"从单点对照升级为**四点趋势证据**。

**对"长尾优势"的重要修正（如实记录）**：B 组分桶分析显示，早期版本的长尾覆盖
（v1 Top-50 长尾占比 8.0%、v2 5.2%）有相当部分来自**碰撞展开的"任意成员"机制**——
按 video_id 顺序展开等于随机把一批长尾视频塞进列表。消除碰撞（b3）后长尾占比
降至 **0.26%**，回到与原生 ID 生成一致的行为（raw 0%、itemcf 0.01%）。
**结论修正：语义 ID 生成本身不自动带来长尾/冷启动覆盖；早期的长尾信号是配置副产物，
要做长尾覆盖需要显式的多样性/探索机制。**

**代价**：b3 每个物品多 1 个 token（解码 4 步而非 3 步），dense 评估单用户延迟
279ms（b1）→ 557ms（b3）（beam=50，CPU）。

### 6.6 训练预算（收敛）与种子方差（2026-10-07 实测）

针对"只训 1 epoch、对比单种子"两个质疑，补做**收敛对照**与**三种子方差**实验。

**设置**：sid-b3 与 raw 各新增 3 次训练——seed42×3 epoch（收敛曲线）、seed43×1 epoch、
seed44×1 epoch（种子方差）；数据/特征/超参与主实验完全一致；seed42×1 epoch 引用主表检查点；
全部新检查点做双协议评估。实测总计 **24,592s（6.8h）**；产物
`results/experiments/convergence_campaign.json` 与 `train_gen_{sid-b3,raw}-{e3,s43,s44}.json`；
复现：`python scripts/run_convergence_campaign.py`。

**收敛曲线（逐 epoch 损失）**

| epoch | sid-b3 训练 | sid-b3 验证 | raw 训练 | raw 验证 |
|---|---|---|---|---|
| 1 | 2.333 | 3.245 | 4.101 | 6.314 |
| 2 | 1.609 | 3.253 | 3.407 | 6.545 |
| 3 | 1.483 | 3.301 | 3.160 | 6.574 |

但 sid-b3 在验证损失上升的同时四项排序指标全升——**教师强制损失不能替代下游排序评估**。

**对两个原始问题的回答**：

1. **收敛后追平是否保持？** 不止保持：3 epoch 同预算下 sid-b3 四项全面领先
（dense +15.4% / +24.7%；采样 +1.5% / +1.6%）。"欠训练"质疑被正面回应，
且方向对 SID 有利（其 1→3 epoch 增益大于 raw）。
2. **~1.5% 差距是否超种子噪声？** 分指标、分协议：① dense recall@50 的差距（-0.05pp）
**在种子噪声内**（三种子跨零，|均值| < 1σ）——稠密协议上已无可检测差距；
② dense ndcg@10 的优势（+1.77pp）与采样协议两项劣势（-1.9 / -1.6pp）三种子方向一致——
**超噪声但幅度小**：1 epoch 下采样协议存在可测的小额劣势；
③ 扩大预算后该劣势被翻转（3 epoch 采样 +0.75 / +0.47pp，约 1σ 量级——弱证据）。
3. **局限（如实标注）**：3 epoch 对照为**单种子**（以 1 epoch 三种子噪声作参照标尺：
dense 两项领先幅度为标尺的 6× / 25×，采样两项仅约 1×）；未做超参搜索；
更大预算（>3 epoch）与"多种子 × 多 epoch"矩阵未跑。

### 6.7 E3：行为 token 消融（2026-10-07 实测）

训练序列原本给每个历史行为附 1 个 watch_ratio 五档**行为 token**；E3 关闭该 token
（config `use_actions: false`，新变体 `sid-b3-na`），其余与 sid-b3 完全一致，
seed42 × 1 epoch 对照：

| 指标 | sid-b3-na | sid-b3（seed42） | 配对差 | 相对 | b3 三种子范围（1ep） |
|---|---|---|---|---|---|
| dense recall@10 | 0.008142 | 0.008349 | -0.0002 | -2.5% | [0.007293, 0.008349] |
| dense recall@50 | 0.037035 | 0.037754 | -0.0007 | -1.9% | [0.034177, 0.037754] |
| dense ndcg@10 | 0.5035 | 0.5178 | -0.0143 | -2.8% | [0.4528, 0.5178] |
| 采样 HR@10 | 0.4550 | 0.4695 | -0.0145 | -3.1% | [0.4565, 0.4695] |
| 采样 NDCG@10 | 0.2506 | 0.2677 | -0.0171 | -6.4% | [0.2534, 0.2677] |

**结论（如实）**：五项指标全部方向为负但幅度小。以 b3 的三种子分布作噪声参照：
**稠密协议三项完全落在分布内**（无可检测差异）；**采样协议两项略低于三种子下沿**
（低 0.15~0.27pp），即可能存在的正贡献小于当前可分辨精度。
**watch_ratio 行为 token 在本配置下未带来可检测的收益**——"行为强度 token 有增益"
的常见假设未获支持。候选解释（均为假设，未验证）：目标只生成 SID、行为 token
仅修饰 context；五档信号与"看过"高度冗余；1 epoch 预算下细粒度信号难学。

**附带工程事实**：关闭行为 token 使序列 105 → 85 token（-19%），dense 评估快 17%
（651s vs 786s）；训练耗时相当（1,896s，79 samples/s）。
产物：`e3_behavior_token_ablation.json`、`train_gen_sid-b3-na.json`。

### 6.8 D2：beam 成本-质量 Pareto 曲线（2026-10-07 实测）

gen-sid-b3 在 beam ∈ {1, 2, 5, 10, 20, 50} 下的稠密全观测评估（beam ≤ 20 为本次实测，
beam=50 引用主表；同机同线程数，延迟口径一致）：

| beam | recall@50 | ndcg@10 | ndcg 保留率 | coverage@50 | ms/用户 | 相对延迟 |
|---|---|---|---|---|---|---|
| 1 | 0.00044 | 0.0611 | 11.8% | 2.8% | 34 | 6% |
| 2 | 0.00108 | 0.1330 | 25.7% | 5.1% | 52 | 9% |
| 5 | 0.00309 | 0.2740 | 52.9% | 8.9% | 80 | 14% |
| 10 | 0.00710 | 0.4661 | 90.0% | 11.2% | 132 | 24% |
| 20 | 0.01512 | **0.5179** | **100.0%** | 13.3% | 256 | 46% |
| 50 | **0.03775** | 0.5178 | 100.0% | 15.9% | 557 | 100% |

**结论**：① **top-10 质量在 beam≈20 饱和**（ndcg 0.5179 ≈ beam50 的 0.5178），
延迟仅为 beam50 的 46%——直出 top-10 场景的最优点；② beam=10 保留 90% 的 ndcg、
延迟降到 24%；③ **recall@50 受候选清单长度约束**（beam ≤ 20 时列表本身不足 50 条）——
"生成粗排 + 精排"的两段式需要 beam50 长列表；④ coverage@50 随 beam 单调上升
（2.8% → 15.9%），beam 同时是多样性旋钮。
产物：`beam_pareto.json` 及 `eval_gen-sid-b3_beam{1,2,5,10,20}.json`（排名列表已存档）。

### 6.9 C2：SASRec-lite 标准基线（阴性结果与回声陷阱诊断，2026-10-07 实测）

动机：补齐工业界公认的序列推荐标准基线（对照表此前只有自实现的 GRU4Rec-lite）。

**方法与差异（如实声明）**：因果自注意力 + 共享物品嵌入头（Kang & McAuley, ICDM 2018），
逐位置监督"下一物品"；与论文实现的差异：全词表交叉熵（与生成式模型同损失族）、
pre-LN、左 padding + 窗口内绝对位置、lite 尺寸（d64 / 2 层 / 2 头，150k 样本 × 6 epoch，
与生成式模型同数据预算）。实现经 5 项单测 + smoke 验证，评估链路经手工复算核验。

**结果（全部实测，且两轮训练逐 epoch 完全复现）**

| 协议 | 指标 | SASRec-lite | 对照：gru-raw | 对照：gen-raw |
|---|---|---|---|---|
| 稠密（1,411 用户） | recall@50 / ndcg@10 | 0.02862 / 0.3948 | 0.03713 / 0.5640 | 0.03833 / 0.4966 |
| 采样（2,000 用户） | HR@10 / NDCG@10 | 0.3340 / 0.1929 | 0.5010 / 0.2767 | 0.4825 / 0.2779 |

（SASRec-lite 稠密单用户延迟仅 0.77ms——单次前向、无生成；coverage@50 19.5%。）

**结论（阴性）**：SASRec-lite 在两个协议上均弱于 GRU4Rec-lite 与生成式模型，
在主表中游偏下（介于 gen-sid-v2 与 gen-sid-b1 之间）。这不是实现错误（见诊断链），
也不代表完整 SASRec 的实力（未做超参搜索/长序列，见"局限"）。

**诊断链（本节的另一半价值：把可疑的阴性结果查到底）**

1. **管线核验**：手工复算 sampled 评估逐用户得分与官方输出精确一致（d128 版 0.2075）；
   d64 版两轮训练逐 epoch loss、两协议指标完全一致（确定性复现）。
2. **训练分布 0.99 ≠ 泛化**：模型在其训练样本上 HR@10 = 0.99（d128），
   初看"拟合良好"——进一步发现是记忆 + 下述回声策略。
3. **回看率随时间衰减（数据特性发现）**：target 出现在 context（最近 20 个行为）中的比例——
   训练窗样本 **28.1%**、常规未来窗口（t>t0 非末位 pivot）**7.2%**、LOO 最终项仅 **3.4%**。
   KuaiRec 的密集回看/连续观看行为随数据集时间显著衰减；训练与评估分布的这一差异
   对所有模型都存在，但影响不均。
4. **回声策略证据**：在 LOO 上，"context 最后一项"的平均得分 **5.59** vs 真实目标 **0.68**，
   **84.7%** 的用户上末项得分 ≥ 目标——模型把"再推刚看过的最后一个视频"当成了高优策略
   （训练期"下一行为 = 上一行为的重看/同带延续"是频率最高的模式）。
5. **容量消融（d64 → d128，其余相同）**：训练 loss 4.90 → 4.58（拟合更强），
   但 LOO HR@10 **0.334 → 0.2075**（回声策略被放大）；稠密 recall@50 0.0286 → 0.0293（持平）。
   "加大模型"没有修好它，反而加深了分布过拟合。

**局限（如实标注）**：本实现为 lite 档（20 项窗口、无超参搜索、无长序列训练）；
"SASRec-lite 弱于 GRU4Rec-lite" 的结论仅对本配置成立，不能外推为方法级结论。
产物：`train_sasrec.json`、`eval_sasrec.json`、`lists_sasrec.npz`；
d128 消融日志存档 `c2_attempt_d128.log`。

### 6.10 E5：冷启动定义细化（"首次曝光时间"口径，2026-10-07 实测）

口径升级：把冷启动从"训练窗零曝光（热度近似）"细化为**按物品首次曝光时间定义的真·上新**——
首次出现时间（大矩阵 ∪ 小矩阵 timestamp 最小值）晚于训练窗截止 t0 即"上新物品"。
词表中上新物品 **1,144 / 10,728（10.7%）**；评估目标中上新目标 1,226 个。

| 方法 | 上新目标 recall@50 | 老目标 recall@50 | Top-50 中上新物品槽位占比 |
|---|---|---|---|
| pop | 0.0000 | 0.0082 | 0.00000 |
| itemcf | 0.0000 | 0.0586 | 0.00000 |
| gen-sid（v1） | 0.0000 | 0.0152 | **5.39%** |
| gen-sid-v2 | 0.0082 | 0.0249 | 3.62% |
| gen-sid-b1 | 0.0000 | 0.0290 | 1.64% |
| gen-sid-b3 | 0.0000 | 0.0378 | 0.16% |
| gen-raw | 0.0000 | 0.0384 | 0.00000 |
| gru-raw | 0.0000 | 0.0372 | 0.00000 |
| sasrec | 0.0000 | 0.0287 | 0.00000 |

**发现**：① **上新目标几乎不可命中**——1,226 个上新目标上除 gen-sid-v2 的微弱命中（0.0082）外
全部为 0，"命中未来会看的新视频"对全部方法都是未解问题；② **只有 SID 家族会给上新物品曝光**
（内容寻址的结构性效应：新物品只要有内容落入码本区域即可进 beam 候选），且曝光份额随碰撞处理
完善大幅收窄（5.39% → 3.62% → 1.64% → 0.16%），非 SID 方法（含 itemcf/raw/sasrec）严格为 0——
与 §6.3/§6.5 的"碰撞展开副产物"修正一脉相承；b3 的 0.16% 是纯 SID 结构下仅存的微弱信号。
产物：`coldstart_analysis.json`；脚本 `scripts/analyze_coldstart.py`。

### 6.11 E6：列表内多样性与新颖性（2026-10-07 实测）

指标（均为 Top-50、逐用户后平均）：ILD@50 = 列表内两两内容特征余弦距离（1 − cos）均值；
Novelty@50 = 物品平均自信息 −log2(p)（p = 训练窗热度占比，Laplace 平滑）。

| 方法 | ILD@50 | Novelty@50 | coverage@50 |
|---|---|---|---|
| pop | 0.805 | 10.63 | 0.50% |
| itemcf | 0.819 | 11.46 | 0.83% |
| gen-sid（v1） | 0.363 | **13.92** | 21.8% |
| gen-sid-v2 | 0.716 | 13.12 | 18.9% |
| gen-sid-b1 | 0.774 | 13.01 | 18.5% |
| gen-sid-b3 | 0.813 | 11.99 | 15.9% |
| gen-raw | **0.861** | 11.95 | 14.8% |
| gru-raw | 0.824 | 11.61 | 2.6% |
| sasrec | 0.847 | 11.89 | 19.5% |

**解读**：① **新颖性上的"碰撞副产物"第三次复现**——v1 新颖性最高（13.92），但消除碰撞的 b3
回落到与原生 ID 生成同级（11.99 vs 11.95）；连同 §6.3（长尾占比）与 §6.10（上新曝光），
"SID 生成不自动带来长尾/多样性"的证据链在三类指标上闭合。② v1 的 ILD 极低（0.363，列表高度
集中于同一内容区域）同样是碰撞展开的直接后果（同组 = 同内容带）；b3 恢复至 raw 同级（0.81 vs 0.86）。
③ 工程含义：多样性/探索需要在解码层显式设计（§6.3）；评测面板自此含 ILD/新颖性两个可量化维度。
产物：`diversity_metrics.json`；脚本 `scripts/analyze_diversity.py`（指标实现含 4 项单测）。

## 7. 负结果与如实声明（不包装）

1. **初版配置下**，"SID 生成优于原生 ID 生成"（TIGER 论文的隐含假设）**不成立**；
   但**后续 B 组（§6.5）把它修正为"基本追平"**：修复碰撞处理与内容特征后，
   b3 在两个协议上达到 raw 的 97.3%~98.5%。**"负结果 → 受控诊断 → 修复 → 追平"
   的完整闭环，以及期间主动推翻的一个长尾结论（§6.3 修正），是本项目的核心研究回答。**
2. 主表模型仅训练 1 epoch（150k 样本）；已补 3 epoch 收敛对照（§6.6，单种子）与三种子方差——"欠训练"质疑得到数据回应（3 epoch 下 sid-b3 全面反超同预算 raw）；未做超参搜索，数字仍是轻量预算下的结论，不是调优后的上限。
3. **行为 token 消融为负结果（§6.7）**：去掉 watch_ratio 行为 token（sid-b3-na）后，五项指标与 b3 的配对差全部落在种子噪声内（稠密协议）或略低于三种子下沿 0.15~0.27pp（采样协议）——"行为强度 token 带来增益"的常见假设在本数据上未获支持，如实记录。
4. **标准基线为阴性结果（§6.9）**：SASRec-lite 在两个协议上均弱于 GRU4Rec-lite 与生成式模型；经诊断链（管线三重核验 / 回看率随时间的分布漂移 28.1%→7.2%→3.4% / 回声策略证据 / 容量消融）确认为"数据分布特征 × 短窗口点积打分"的系统性效应而非实现错误；结论仅限 lite 档配置，不代表完整 SASRec。
5. 合成数据仅用于单元测试；所有评估数字均来自真实 KuaiRec 数据。
6. 本项目是离线研究原型：**无线上 A/B、无线上收益声明**。

**待运行（明确列出）**：完整版 SASRec（超参搜索/长序列——本版为 lite 档，§6.9）、
prefix 共享/KV 缓存推理优化、
更大训练预算（>3 epoch）× 更多种子的收敛矩阵。

## 8. 工程问题与修复记录（面试可讲）

| 问题 | 表现 | 根因与修复 |
|---|---|---|
| RQ-VAE 码本坍缩 | 唯一 SID 仅 593 | 缺 STE → 编码器无重建梯度；补 STE + 死码重启 + 特征标准化 |
| CPU 训练慢 10 倍 | 19 samples/s | 8 线程超订；改 4 线程 → 206 samples/s |
| 检查点加载失败 | RuntimeError(state_dict) | 位置嵌入 max_len 训练/推理不一致；存入检查点并统一重建 |
| caption 解析崩溃 | pandas Buffer overflow | 换 python 引擎；8 行缺字段置空串（发现类型污染 NaN） |
| 数据下载不可行 | 官方源 42 KB/s | 多源策略（镜像矩阵+官方小文件），校验后使用并全量披露 |
| npz 逐行取值 | 训练"假死"（CPU 满、无进度） | npz 每个 key 每次取值都重新解压+CRC——先物化数组再循环（py-spy 定位） |
| 默认初始化过大 | 起始 CE≈21（正常≈log K）→ 发散 NaN | 改用原版 SASRec 的 N(0, 0.02) 初始化 + 非有限 loss 跳过保护 |
| 索引映射遗漏 ×2 | IndexError / 评估结果无效 | 视频 ID→词表索引映射在训练与两处评估统一落实（smoke/手工复算抓出） |
